# WorkSpec Studio WebMCP demo narration

Upload `workspec-studio-webmcp-demo.mp4` to ElevenLabs Studio as a **New video voiceover** project. Mute or remove its existing audio track, then add the following clips at the indicated start times.

## 00:00 — Titleå

Architecture decisions usually fragment across diagrams, spreadsheets, cloud pricing tabs, and ADR documents. WorkSpec Studio turns that into one shared, reviewable workflow between a person and an agent.

## 00:17 — Context architecture

We begin with the application architecture. Through WebMCP, the agent can turn intent into a structured C4 proposal directly inside the same canvas the person is reviewing.

## 00:31 — Logical architecture

This is not a screenshot or an opaque generated document. Every actor, system, domain, relationship, and container remains interactive, inspectable, and editable by the person.

## 00:46 — Deployment architecture

Logical and deployment views separate business ownership from runtime placement. Components can belong to one logical domain while being deployed inside a different user interface, API, or worker container.

## 01:02 — Agent activity

Every successful agent operation is recorded in the collapsible Agent Activity history. The collaboration stays visible without cluttering each page with extra banners.

## 01:14 — Infrastructure plan

From the architecture, WorkSpec derives an editable, provider-neutral infrastructure shopping list. Deployable elements become compute, database, and messaging requirements, while actors and external systems are intentionally excluded.

## 01:32 — Collaborative refinement

The person and agent can refine quantity, size, availability, and notes together. Here, the incident database is made large and highly available, and both provider estimates update from the same requirement.

## 01:49 — Provider comparison

WorkSpec then maps the identical shopping list to Microsoft Azure and Amazon Web Services. The monthly figures are deterministic planning estimates, not live quotes, so the comparison remains reproducible and understandable.

## 02:06 — Decision draft

The agent prepares an Azure recommendation because it satisfies the same six requirements at the lower estimate. Crucially, this is still a visible, editable draft. The agent cannot silently create the decision record.

## 02:22 — Recorded ADR

Only after explicit human approval does WorkSpec generate the architecture decision record and selected provider model. The rationale, costs, and architectural consequences remain traceable.

## 02:37 — Export

Finally, the complete dot WorkSpec workspace can be downloaded or exported through WebMCP. The architecture, infrastructure plan, provider mappings, and decision remain portable files the team owns. WorkSpec Studio makes WebMCP shared work, not hidden automation.

## Voice direction

Use a grounded, confident product-builder voice. Keep the delivery conversational and understated, at roughly 0.95× speed. Avoid a commercial-announcer tone. Generate each section separately so a flawed sentence can be regenerated without affecting the rest of the timeline.
